## 修复：开关下载型/触发型方案时 hosts 文件被加入空行

开关 as_hosts=false 的方案时，onToggleItem 无条件调用 writeHostsToSystem，
导致 hosts 文件被不必要地重写，append 模式下可能引入空行。

三层修复：
1. `List/index.tsx` onToggleItem — as_hosts=false 的节点只更新列表状态，
   不调用 writeHostsToSystem（与 applyChangedRemoteHostsToSystem 的逻辑对齐）
2. `aggregate.rs` collect_selected — 跳过空内容的 entries，避免 join("\n\n")
   产生空行
3. `write.rs` make_append_content — 内容为空时不再追加换行，head 也 trim_end
   去除尾部残留空白

Git commit: 8d300b0，已推送到 origin/master。

## 新增：file:// 指向 .ps1 的脚本触发型方案

远程方案 URL 为 `file:///C:/.../xxx.ps1`（本机 PowerShell 脚本）时，
刷新即**触发型运行**：自动执行该脚本，运行结果写入内部 entries 供右侧
编辑器显示，绝不进入系统 hosts 管线；有 save_path 时镜像输出到该文件。

改动：
- `src-tauri/src/script_trigger.rs`（新模块）— `script_path_from_url` 识别
  file:// + .ps1（大小写不敏感、支持 localhost 形式、%XX 解码、
  Windows 盘符去前导斜杠）；`is_script_trigger_url` 供各处复用
- `refresh.rs` — 主干新增脚本分支：`run_script_trigger`（powershell.exe
  -NoProfile -ExecutionPolicy Bypass -File，CREATE_NO_WINDOW 隐藏窗口，
  60s 超时 + kill_on_drop，stdout/stderr 各截断 1MiB）→
  `format_script_run_output` 组装预览文本写回 entries；执行成功退出码
  非 0 时刷新算完成但按失败推送通知（附退出码）；脚本无法启动按
  Fetch 错误返回并推送失败通知
- `aggregate.rs` `is_on` — script-trigger URL 的方案永远不进入系统 hosts
  （防 as_hosts 缺省/为 true 的旧配置泄漏输出）
- `commands.rs` + `lib.rs` — 新增 `pick_file_path` 命令（打开文件对话框）
- `EditHostsInfo.tsx` — URL 行新增「浏览本地文件」按钮（选择后填入
  file:/// 格式）；.ps1 URL 时显示触发型说明、禁用 as_hosts 开关，
  onUpdate/onSave 强制 as_hosts=false
- 9 种 i18n 语言文件新增 `url_pick_file`、`url_script_desc` 文案

验证：TS typecheck 零错误；cargo test 167 个全过（含真实 powershell.exe
执行 .ps1 的端到端测试）；全量 cargo check 无新增警告。

## 修复：ps1 触发型运行结果乱码 + 新增产物输出目录

乱码原因：中文 Windows 上 PowerShell 5.1 向管道输出默认 GBK（OEM
936），Rust 侧 from_utf8_lossy 按 UTF-8 解码全变替换字符。

修复（refresh.rs + Cargo.toml）：
- spawn_script（Windows）改为 `-Command` 包装：
  `[Console]::OutputEncoding=[Text.Encoding]::UTF8; & '<path>'; exit
  $LASTEXITCODE`（路径单引号包裹、内嵌单引号翻倍；`exit $LASTEXITCODE`
  保持脚本退出码，实测 -Command 单独跑退出码会变 1）；保留
  CREATE_NO_WINDOW / ExecutionPolicy Bypass
- 新增 `decode_script_bytes`：先严格 UTF-8，失败用 encoding_rs::GBK
  兜底（CP936/GB18030），再 lossy；`truncate_output` 改为按字符截断
  （不再有字节边界 panic 风险）
- Cargo.toml 新增依赖 `encoding_rs = "0.8"`（v0.8.41）

新增功能（用户要求：ps1 运行产物文件应与脚本同位置，可由本地保存
路径指定）：
- `run_script_trigger(path, work_dir)` 增加工作目录参数：
  `resolve_script_work_dir` — save_path（且 save_path_enabled 未关）
  指定时作为脚本工作目录（自动创建；指向文件则退回脚本目录），否则
  默认脚本自身所在目录；spawn 时 `.current_dir(cwd)`
- refresh_one_inner 脚本分支：save_path 语义从「运行日志镜像文件」
  改为「产物输出目录」，删除 write_save_copy 调用
- 9 种 i18n 的 `url_script_desc` 追加产物输出目录说明

验证：cargo test 170 个全过（新增 decode GBK/UTF-8、resolve_script_
work_dir 单测；端到端测试用 GBK 编码脚本断言中文输出正确 + 产物文件
默认落脚本目录、指定目录时落指定目录）；typecheck 零错误。release
exe 已重建并复制到 build-artifacts/windows-x64/。

## 教训：release exe 必须用 tauri CLI 构建

现象：便携 exe 打开后界面显示 devUrl（127.0.0.1:8220 连接失败页/白屏）。

原因：用裸 `cargo build --release` 构建时没有启用 `custom-protocol`
特性（tauri CLI 在 `tauri build` 时自动注入 `--features
tauri/custom-protocol`），release 版没有内嵌 build-tauri 前端资源，
应用退回加载 devUrl。

修复：`npx tauri build --no-bundle`（跳过安装包；WiX 已缓存，全量
bundle 也可行）。验证方法：读 exe 二进制 ASCII 找 `assets/` +
`renderer-*.js` 标记；无标记 = 未内嵌（坏），有 = 好。正常 exe
约 8.3MB，坏的约 7.9MB。构建产物约定：只保留
build-artifacts/windows-x64/switchhosts.exe + README.txt。
